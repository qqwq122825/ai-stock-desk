# 投研委员会（外部 AI 模式）—— 建仓/加仓前必须通过

你要主持一次 11 人投研委员会，审核是否买入某只股票。项目根目录就是当前目录（有 `agent_cli.py`）。
系统规定：**没有通过委员会的股票，买单会被拒绝**。

> 如果设置了内置大模型，也可以直接 `python3 agent_cli.py committee run <代码>` 让程序自己跑完（1~3 分钟）。
> 下面是你自己扮演 11 个角色的流程。**如果你能启动子代理（subagent），5 位分析师请并行交给 5 个子代理，
> 多空研究员也交给两个独立子代理**——角色之间互相独立思考，效果明显好于一个人分饰多角。

## 0. 开会
```
python3 agent_cli.py committee start <代码> [--intent open|add]
```
输出里有 `run_id`、`dossier_file`（档案，所有角色只能依据它和你的联网搜索结果）、`roles_file`。
**阅读 `prompts/committee_roles.md`**：每个角色 = `_common` 段 + 该角色段。严格以该角色身份和立场输出 JSON。

## 1. 五位分析师（互相独立，不看彼此的结论）
依次（或并行）扮演 technical、capital、news、fundamental、sentiment。每位把 JSON 存到文件后提交：
```
python3 agent_cli.py committee opinion <run_id> technical data/op_technical.json
```
（news 分析师如果能联网，请搜索该股近 3 日新闻作为补充，并在 points 里注明来源）

## 2. 多空辩论（默认 2 轮）
- 第 1 轮：bull 读 5 份分析写多头论证 → 提交 `--round 1`；bear 读 5 份分析 + 多头论证，写空头论证并逐条反驳 → `--round 1`
- 第 2 轮：bull 逐条反驳 bear → `--round 2`；bear 再逐条反驳 bull → `--round 2`
- 扮演多头时就全力找做多理由，扮演空头时就全力找风险，**不要手下留情**

## 3. 研究主管 → 交易员 → 风控官
- research_manager：读全部发言，裁判，提交
- trader：按主管结论给具体方案（入场上限、止损、目标、持有天数、仓位、盈亏比），提交
- risk：结合档案里的账户、大盘状态、风控参数审查，有权 `"veto": true`，提交

## 4. 组合经理拍板
pm 综合全部意见写最终 JSON（字段要求见 roles 文件 `## pm`，必须包含 decision、position_pct、entry_max、stop_loss、
target、trailing_pct、max_hold_days、thesis、invalidation、watch_points），然后：
```
python3 agent_cli.py committee final <run_id> data/op_pm.json
```
系统会自动执行门禁：风控否决 → 不通过；置信度 < 0.6 → 不通过；仓位不超过风控官上限。

## 5. 之后
- 结论 `approved`：30 小时内可以按 `decide` 下买单（仓位 ≤ 委员会仓位，现价 ≤ entry_max）。成交后系统自动用 pm 的内容生成持仓计划。
- 结论 `rejected`：本次不买，在 journal 里记一句原因。
- `python3 agent_cli.py committee show <run_id>` 可回看整场会议；网页「委员会」页也能看。

注意：所有角色只能用档案数据和真实检索到的信息，**不准编造**数据和新闻。数据缺失就写"缺失"。
